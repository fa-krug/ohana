# Ohana

One app for the whole family: a shared **calendar**, the family's **finances**, **meals**
(recipes, meal plan, shopping lists), **doctor appointments** and an **AI assistant** that
works across all of them.

Ohana is open source and **self-hosted**: you run the server (one Docker image, one SQLite
file) at home or on any small machine, and the family uses the **native app for iPhone, iPad
and Mac** ([`apple/`](apple)). There is no web app: the server only serves the API and the
few pages that need your server's own address (signing in with passkeys, the first-run setup,
invite links).

**Website and documentation: [ohana.fa-krug.de](https://ohana.fa-krug.de)** (a
[quick start](https://ohana.fa-krug.de/quickstart), the self-hosting guide, the API reference).

## Features

- **Families and people:** several families per account, members as **editor** (changes
  everything) or **viewer** (only looks), invite links, members without an account (children,
  grandparents) with birthdays. An administrator creates accounts with one-time setup links.
- **Calendar:** the family's year at a glance: vacation, public holidays, sick days, day-care
  closures; entry types per year with roles that show **days nobody covers**; notes; timed
  events (e.g. a booked doctor's appointment); birthdays; an **iCalendar feed** for Apple,
  Google or any calendar app.
- **Finance:** transactions, accounts, a category tree, transfers and split bookings, **CSV
  import** of bank statements with saved formats, monthly overviews, comparisons and a
  benchmark; categorizing with the assistant.
- **Meals:** recipes (with kitchen-machine steps, photos, tags), a **meal plan** that picks
  recipes sharing ingredients and skips days the family is away, **shopping lists** grouped by
  aisle that work offline, a cook view, and recipes and photos generated by AI.
- **Appointments:** searches that watch Doctolib and jameda for free appointments and notify
  you (Germany; can be turned off per server); booked ones go into the calendar.
- **Assistant:** chats with any OpenAI-compatible model (a cloud provider or your own, e.g.
  Ollama) that can read and change the calendar, finances, meals and appointments, with undo;
  web search with your own key.
- **Notifications** to Pushover, Pushbullet, Telegram, email or **ntfy** (self-hostable push):
  new appointments, days without cover, tomorrow's shopping list, a finished assistant answer.
- **Two languages:** English and German.

## Getting started

1. **Run the server.** With Docker Compose and a domain with HTTPS:

   ```bash
   curl -O https://raw.githubusercontent.com/fa-krug/ohana/main/docker-compose.yml
   curl -o .env https://raw.githubusercontent.com/fa-krug/ohana/main/.env.example
   # set APP_URL and AUTH_SECRET in .env, put a reverse proxy with HTTPS in front of port 8000
   docker compose up -d
   ```

   The [quick start](https://ohana.fa-krug.de/quickstart) walks through it; the full guide
   (reverse proxy, backups, updates, AI, notifications, turning modules off) is
   [docs/self-hosting.md](docs/self-hosting.md).
2. **Create the first account.** Open `https://<your server>/setup` (or connect the app
   right away: it opens the setup for a fresh server). The first account is the administrator.
3. **Connect the app.** In the app, enter your server's address and sign in. The app gets its
   own API token; without a server it shows a read-only demo family. Building the app: see
   [apple/README.md](apple/README.md).

## How it fits together

```
 iPhone / iPad / Mac app ──HTTPS──▶  ohana (server/)            ohana-worker (same image)
   (apple/, SwiftUI)                  API /api/v1               assistant turns, appointment
                                      sign-in pages             searches, notifications, backups
                                            └──── /app/data: SQLite (WAL), photos, backups ────┘
```

- **[`server/`](server):** TypeScript on Node.js: [Hono](https://hono.dev) for HTTP, Drizzle
  ORM over SQLite, passkeys and passwords, Vitest. The **API** is described in
  [docs/openapi.yaml](docs/openapi.yaml); personal API tokens (from the app's account
  settings, `Authorization: Bearer ohana_…`) let scripts and AI agents use it too.
  `GET /api/v1/server` tells clients the version and which modules are on.
- **[`apple/`](apple):** the SwiftUI app for iOS/iPadOS 26 and macOS 26 (XcodeGen project).
- **[docs/plan.md](docs/plan.md):** how Ohana came to be (it replaced three earlier apps) and
  the decisions behind it.

## Development

```bash
cd server
npm install
npm run db:migrate   # creates ./data/ohana.db with the shared units and ingredients
npm run dev          # http://localhost:3000 (API + sign-in pages, restarts on changes)
npm run worker       # the background worker, in a second terminal
npm run mock-ai      # a scripted stand-in AI on http://localhost:4011/v1 (model mock-large);
                     # run server and worker with AI_ALLOW_PRIVATE_ENDPOINT=1 to use it
npm test             # Vitest
npm run typecheck
```

Point the app at `http://<your machine>:3000` to try it against your checkout. Schema
changes: edit `server/lib/db/schema*.ts`, then `npm run db:generate`. Settings come from the
environment: [server/.env.example](server/.env.example). Locked out? `npm run setup-link --
<email>` prints a new setup link.

The website ([ohana.fa-krug.de](https://ohana.fa-krug.de)) is [`docs/`](docs): VitePress,
`cd docs && npm install && npm run dev`; it's published to GitHub Pages from `main`.

See [CONTRIBUTING.md](CONTRIBUTING.md) for how to contribute and [SECURITY.md](SECURITY.md)
for reporting vulnerabilities.
